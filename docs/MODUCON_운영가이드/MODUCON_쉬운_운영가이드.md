## 2쪽 · 홈페이지부터 열어 볼까요?

폴더는 서랍, 파일은 그 안의 종이라고 생각하세요.

### 1. 프로젝트 폴더를 찾으세요

현재 컴퓨터에서는 탐색기를 열고 아래 주소를 주소창에 붙여 넣으세요.
C:\Users\Admin\Documents\업무\moducon-js

다른 컴퓨터에서 ZIP으로 받았다면 moducon-js.zip을 오른쪽 클릭 → “모두 압축 풀기”를 누르세요. 압축 파일 안에서 바로 수정하지 마세요.

### 2. dist → index.html을 두 번 누르세요

브라우저가 열리면 홈 화면이 보입니다. 메뉴를 눌러 세션 시간표, 상세 페이지, FAQ를 열어 보세요.

### 3. 수정 전에 폴더를 하나 복사하세요

moducon-js 폴더를 통째로 복사해 moducon-js_백업_날짜라는 이름으로 보관하세요. 백업 폴더는 프로젝트 바깥에 둡니다.

| 서랍 이름 | 들어 있는 것 |
| --- | --- |
| dist/index.html | 홈 화면의 글자와 구성 |
| dist/session/index.html | 전체 세션 시간표 |
| dist/session/00-00/index.html | 예시 세션 상세 |
| dist/faq/index.html | 자주 묻는 질문과 답변 |
| dist/assets/ | 사진 · 배경 · 영상 · 글꼴 |

**인터넷에서 확인하려면**

아래 링크는 현재 소유자에게 접근이 제한된 배포본입니다. 사이트를 만든 계정으로 로그인해 확인하세요.

## 9쪽 · 주소의 화살표를 옮깁니다

moducon.modulabs.co.kr 주소를 그대로 사용하면서 새 사이트를 보여 줍니다.

`moducon.modulabs.co.kr` → 지금: Framer / 연결 후: 새 Sites 사이트

도메인은 집 주소, 사이트는 집 안의 내용, DNS는 주소가 어느 집을 찾아갈지 알려 주는 안내판이라고 생각하세요.

| 현재 확인한 것 | 내용 |
| --- | --- |
| 원래 주소의 연결 대상 | Framer 사이트 |
| 새 사이트의 배포 상태 | Sites에 배포됨 · 현재 소유자 접근으로 제한 |
| 새 사이트의 맞춤 도메인 | 아직 등록된 도메인 없음 |
| DNS 관리 서비스 | 공개 NS 응답상 AWS Route 53로 추정 |

실제 AWS 계정과 담당자는 아직 확인되지 않았습니다. 도메인을 산 회사와 DNS를 관리하는 회사가 다를 수 있습니다. 지금은 실제 연결을 변경하지 않고, 나중에 따라 할 절차를 정리한 상태입니다.

### 1. DNS를 관리하는 사람을 찾으세요

모두의연구소 도메인 담당자에게 “modulabs.co.kr의 DNS를 수정할 수 있는 분”을 연결해 달라고 하세요. 계정 비밀번호를 이 대화에 적을 필요는 없습니다.

### 2. 새 사이트와 전환할 시간을 정하세요

최종 문구·사진·신청 링크를 확인하세요. 담당자와 함께 접속이 적은 전환 시간을 정하고 기존 Framer 사이트는 유지하세요.

**도메인을 새로 살 필요는 없어요**

이미 사용하는 주소를 계속 씁니다. 이번 연결을 위해 도메인 등록업체나 전체 네임서버를 옮길 필요는 없습니다.

## 10쪽 · 새 연결값을 먼저 받으세요

이 단계는 실제 전환을 준비하는 날 진행합니다.

### 1. 기존 Sites 사이트의 설정을 여세요

chatgpt.com/sites에서 MODUCON 배포 주소가 맞는 사이트를 찾으세요. 설정의 Add domain(도메인 추가)을 열고 moducon.modulabs.co.kr을 입력하세요.

### 2. 나온 DNS 이름과 값을 보관하세요

Sites가 제공하는 연결용 CNAME 값과 인증용 레코드 전체를 복사해 두세요. 인증용 레코드는 TXT 또는 CNAME 등으로 안내될 수 있습니다.

| 종류 | 이름 | 넣을 값 |
| --- | --- | --- |
| CNAME | moducon | Sites가 실제로 발급한 연결값 |
| 인증용 레코드 | Sites가 알려 준 이름 | Sites가 알려 준 인증값 |

**위 표는 입력 양식입니다**

“Sites가 실제로 발급한 연결값”이라는 문장을 그대로 넣으면 안 됩니다. 이 사이트의 새 연결값은 아직 발급받지 않았습니다. 현재 배포 주소를 임의로 CNAME 값에 넣지 마세요.

### 3. 방문자 공개 범위를 준비하세요

일반 공개 홈페이지로 전환할 때는 사이트의 공유 설정에서 인터넷의 모든 방문자가 볼 수 있도록 공개 범위를 설정합니다. 도메인 추가와 공개 설정은 별개입니다.

```text
MODUCON을 원래 주소에 연결할 준비를 해 줘. 새 DNS 연결값과 인증용 레코드를 받아 정확한 표로 정리해 줘. 기존 DNS를 바꾸기 전에는 현재 설정과 복구값을 확인해 줘.
```

메뉴가 보이지 않으면 사이트 소유자 계정과 현재 기능 제공 여부를 확인하세요. 설정 화면의 명칭은 서비스 업데이트로 달라질 수 있습니다.

## 11쪽 · 연결표의 한 줄을 바꿉니다

현재 DNS가 AWS Route 53에서 관리되는 경우의 순서입니다.

### 1. 현재 값을 먼저 보관하세요

AWS 콘솔 → Route 53 → Hosted zones(호스팅 영역) → modulabs.co.kr을 여세요. moducon.modulabs.co.kr의 CNAME 행을 찾고 화면과 값을 보관하세요.

| 항목 | 2026.09.09에 관찰한 값 |
| --- | --- |
| 이름 | moducon.modulabs.co.kr |
| 종류 | CNAME |
| 기존 값 · 복구용 | visual-standards-592710.framer.app. |
| 공개 응답에서 본 TTL | 300초 · 실제 설정 화면에서 다시 확인 |

### 2. Sites가 요구한 인증 레코드를 넣으세요

이름·종류·값을 받은 그대로 입력합니다. 먼저 인증만 가능한 경우에는 완료한 뒤 전환하세요. 연결 변경 후에야 인증이 완료되는 경우에는 안내된 순서로 진행하세요.

### 3. 정한 시간에 기존 CNAME의 값을 교체하세요

moducon CNAME 행을 선택 → Edit record(레코드 수정) → 기존 값을 Sites가 발급한 새 값으로 교체 → Save changes(저장). CNAME의 목적지에는 https://나 /session 같은 경로를 넣지 않습니다.

**이름 입력칸을 확인하세요**

짧은 호스트 이름을 묻는 화면은 moducon, 전체 이름을 묻는 화면은 moducon.modulabs.co.kr입니다. 저장 전 완성되는 이름을 확인하세요.

변경 범위는 moducon 연결과 요구된 인증 레코드입니다. modulabs.co.kr 자체, www, 메일 설정(MX 등), NS는 유지합니다. 같은 이름에 CNAME과 다른 종류의 레코드를 임의로 겹쳐 만들지 마세요.

[AWS 공식 안내: 레코드 수정](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/resource-record-sets-editing.html)

[AWS 공식 안내: CNAME 이름의 제약](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/ResourceRecordTypes.html#CNAMEFormat)

## 12쪽 · 새 화면이 보이면 끝일까요?

주소 · 자물쇠 · 로그인 없는 접속까지 확인하면 완료입니다.

### 1. Sites에서 연결 상태를 새로 확인하세요

도메인 상태를 새로고침하세요. 도메인 연결이 활성 상태이고 HTTPS 인증이 완료되어야 합니다. 보류 상태라면 표시된 오류와 DNS 값을 확인하세요.

### 2. 로그아웃한 새 창에서 확인하세요

브라우저의 시크릿/InPrivate 창에서 아래 항목을 확인하세요. 로그인 요청이 나오면 공개 범위를 다시 확인합니다.

□ https://moducon.modulabs.co.kr/ 에 새 홈이 보임
□ https://moducon.modulabs.co.kr/session/00-00/ 직접 열기
□ /session/과 /faq/ 직접 열기 및 새로고침
□ HTTPS 주소에서 인증서 오류 없음
□ 휴대폰에서 글자·사진·메뉴 정상
□ 신청·지도·영상·공유 버튼 정상

### 3. 다른 연결에서도 확인하세요

휴대폰의 와이파이를 끄고 모바일 데이터로 확인하세요. DNS 정보를 잠시 기억하는 곳이 있어 사람마다 바뀌는 시간이 다를 수 있습니다. TTL 300초여도 모두 5분 안에 바뀐다고 보장할 수는 없습니다.

**문제가 크면 이렇게 되돌립니다**

작업 당일 보관한 기존 CNAME 값으로 복원하세요. 지금 관찰한 복구값은 visual-standards-592710.framer.app. 입니다. 기존 Framer 사이트가 살아 있어야 복구할 수 있습니다. 되돌린 후에도 캐시 때문에 시간이 걸릴 수 있습니다.

새 사이트가 정상적으로 열리고 운영이 안정된 것을 확인한 뒤, 담당자와 기존 Framer의 유지 여부를 결정하세요. 파일을 잘못 수정한 문제는 백업 파일이나 이전 Sites 버전으로 복구합니다.
